## HyperBoost X v1.1.0-beta.1

`v1.1.0-beta.1` is a beta stabilization update focused on testing readiness, safer service behavior, verification tooling, and release discipline across the entire HyperBoost X stack.

This release continues the `1.1.0-beta` line by improving how the project is validated, how critical helpers are tested, and how new changes are verified before broader beta rollout.

## Recommended download

For most users, the recommended file is:

- `HyperBoostXInstaller-v1.1.0-beta.1.exe`

Other assets:

- `HyperBoostX-Portable-v1.1.0-beta.1.zip` for portable/manual extraction use
- `HyperBoostX-Package-v1.1.0-beta.1.zip` for technical packaging or runtime inspection
- `SHA256SUMS.txt` for checksum verification

## Release focus

The primary goals of this beta refresh are:

- strengthen testability for backend, launcher, and desktop service logic
- add real regression coverage for Python and .NET components
- improve the in-app testing and audit experience
- add a one-command verification path for local validation
- establish CI and release-gate workflows for safer iteration
- reduce the gap between feature growth and software quality assurance

## Summary of improvements

### Service testability and safer helper design

Several core helper components were adjusted so they can be tested more directly and fail more safely in constrained environments.

Updated areas include:

- backend logger initialization
- booster process filtering
- app config persistence behavior
- installer verification logic
- Discord webhook payload generation
- NVIDIA Copilot response parsing
- launcher runtime layout resolution

These changes improve maintainability and reduce reliance on manual-only validation.

## Detailed changes

### Backend and shared service improvements

#### Logger hardening

The backend logger path was improved so that restricted or test environments do not fail as aggressively when file logging cannot be initialized normally.

#### Booster process safety filtering

The optimization flow now uses a dedicated process filtering path for non-essential applications through a clearer `should_close_process` decision method.

#### Config persistence testability

`AppConfigService` now supports custom config directory injection, making save/load behavior easier to test without depending on fixed user profile paths.

#### Installer verification hardening

`AppUpdateService` now supports stronger verification logic through checksum-aware validation, including published checksum discovery and hash matching support.

#### Discord webhook payload extraction

Discord reporting logic now exposes a reusable payload builder so webhook formatting can be tested directly without relying only on live POST calls.

#### NVIDIA response parsing test hook

NVIDIA Copilot response parsing is now accessible through a test-friendly entry point so response extraction logic can be validated in isolation.

#### Launcher runtime layout extraction

Launcher path resolution was extracted into a dedicated runtime layout helper, allowing runtime lookup behavior to be tested without relying on the full launcher entry flow.

## Regression testing added

### .NET regression test project

A dedicated desktop-side test project was added:

- `dotnet-tests/HyperBoostX.Tests`

Covered areas include:

- app config save/load round-trip behavior
- updater checksum parsing behavior
- installer validation contract behavior
- Discord webhook payload structure
- launcher runtime layout resolution
- NVIDIA Copilot response parsing

### Python regression tests

Additional backend regression tests were added for:

- booster safety behavior
- tweak contract behavior
- update contract behavior

A test bootstrap helper was also added so tests can be run more consistently from the repository root.

### Unified local verification

A new verification script was added:

- `scripts/verify_repo.ps1`

This script provides a single entry point for:

- Python backend tests
- .NET desktop regression tests

Example usage:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify_repo.ps1
```

Supported options include:

- `-Configuration Release`
- `-SkipPython`
- `-SkipDotnet`
- `-NoRestore`

## Current release maturity

`v1.1.0-beta.1` is a stronger and better-validated beta than the earlier `v1.1.0-beta` snapshot, but it is still intentionally treated as a beta release.

## Known remaining high-risk areas

The following areas still require broader machine validation before a true stable release claim would be appropriate:

- driver update and rollback flows
- repair actions that affect services or system state
- advanced tweaks and low-level configuration changes
- restore and rollback scenarios after system changes
- installer upgrade and uninstall paths
- admin-required operations across different Windows environments
- cross-machine compatibility and edge-case validation

## Recommended use for this beta

This release is recommended for:

- internal QA
- controlled beta testing
- architecture review
- feature validation
- regression verification
- release workflow testing

It is not yet positioned as the final public-stable build.
