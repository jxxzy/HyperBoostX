## Implemented behavior

The feature and action registries are generated under `docs/registry`. Seven registered action IDs cover transparency enable/disable, game capture preference enable/disable, current-user Run entry disable, existing power-plan selection, and bounded old-temporary-file quarantine. The executable action registry is tested against the documented registry. Each mutation uses the shared preview, guard, durable backup, write, read-back and recovery engine. Registry availability is probed; absent settings are not invented. Verification proves the stored configuration, not a performance benefit or another application's behavior.

Diagnostics are snapshots. The dashboard separately samples local CPU, physical memory, and aggregate network traffic every two seconds while visible (or while the user-enabled Memory Guard is active); Processes reports interval-average per-process CPU over a short two-observation sample. Startup diagnostics read auto-start services and scheduled tasks when their WMI providers are available, plus Windows Diagnostics-Performance boot durations when the event is available; task trigger attribution and boot-impact analysis are not implemented. Network diagnostics support a six-probe ICMP sample and an explicit system-resolver lookup with elapsed time; resolver choice is not changed. GPU utilization, VRAM, temperatures, and vendor sensor telemetry remain unavailable. WMI properties retain provider limitations; unsupported sensors and permission failures are shown explicitly. Network packet-loss measurements are based on six ICMP probes and do not guarantee connection quality.
